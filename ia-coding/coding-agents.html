Chapter 1

Let it run.
Fence the field.

Asking for approval on every command looks safe, but people stop reading the prompts after a while. Give the agent room to work, and put hard limits around that room.

    In practice: my own setup

    Production stays out of reach

    My production checkouts live in ~/code. The sandbox blocks that folder, so the agent can't read it, let alone edit it.

    Ask only for what others see

    Just do itown branches, worktrees, commits, pushes to my branches
    Ask me firstopen a PR, post to Jira or Slack, push to main

    Exceptions stay narrow

    gh fails TLS inside the sandbox. The fix was to let only a bare gh command run outside it, never to turn the sandbox off.

    Same idea in Codex: approval mode decides when it asks, sandbox mode decides what it can touch. Start with the defaults and loosen them only for repos you trust.

    Chapter 2

    Every line costs context.
    Keep the ones that prevent mistakes.

    CLAUDE.md is loaded into every session, like onboarding notes for a new teammate. Each line competes for the agent's attention, so a short file gets followed better than a long one.

    The filter, line by line

    If I delete this line, would the agent get something wrong?

        Where the cut lines go

        Nowhere

        Folder layout, strict mode, "use meaningful names". The agent reads the code and already knows the standard conventions.

        A hook

        "Run the linter", "use const". If a tool can check it, enforce it on every edit instead of asking for it.

        A link or a skill

        API contracts and domain knowledge. A skill is loaded only when the task needs it, CLAUDE.md is loaded always.

        The ticket

        "This sprint we're migrating X." It's stale in two weeks and nobody remembers to remove it.

        Keep it alive

        Layer it

        ~/.claude/CLAUDE.mdmy defaults, every repo
        repo/CLAUDE.mdteam rules, in git
        repo/api/CLAUDE.mdlocal rules, closest wins

        Grow it from mistakes

        Same mistake twice? Add a rule, or ask the agent for a retrospective and let it propose one. Mine opens with "living document: updated as I correct things in real sessions".

        Prune it like code

        Review it, cut what no longer changes behavior. A rule that keeps being ignored doesn't need capital letters, it needs a hook (chapter 1).
